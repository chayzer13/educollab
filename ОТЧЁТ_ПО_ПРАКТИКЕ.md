# ОТЧЁТ ПО ПРАКТИКЕ

## Платформа для совместной работы над учебными проектами EduCollab

---

## 1. ЦЕЛЬ И ЗАДАЧИ

### 1.1. Цель проекта

Разработка веб-платформы для совместной работы студентов, преподавателей и менторов над учебными проектами с возможностью публикации проектов, создания команд, отслеживания прогресса, комментирования и оценки работ.

### 1.2. Задачи проекта

1. **Аутентификация и авторизация:**
   - Реализация системы регистрации и входа пользователей
   - Поддержка ролей: студент, преподаватель, ментор, администратор
   - JWT-аутентификация для безопасного доступа

2. **Управление проектами:**
   - Создание, редактирование и удаление проектов
   - Управление видимостью проектов (публичные/приватные)
   - Отслеживание прогресса выполнения проектов
   - Архивирование проектов
   - Загрузка и управление файлами проектов
   - Управление майлстоунами

3. **Управление командами:**
   - Создание команд с лидером
   - Система приглашений в команды
   - Управление участниками команд
   - Привязка проектов к командам

4. **Социальные функции:**
   - Комментирование проектов с поддержкой ответов
   - Система рейтингов проектов
   - Просмотр профилей пользователей
   - Отслеживание активности пользователей

5. **Система уведомлений:**
   - Уведомления о новых приглашениях в команды
   - Уведомления о приглашениях в проекты
   - История приглашений

6. **Статистика и аналитика:**
   - Статистика по проектам и командам
   - Персональная статистика пользователя
   - История активности

7. **Административные функции:**
   - Управление пользователями
   - Управление базой данных
   - Просмотр общей статистики системы

8. **Пользовательский интерфейс:**
   - Современный и отзывчивый дизайн
   - Поддержка тёмной и светлой темы
   - Адаптивная вёрстка для различных устройств

## 2. АРХИТЕКТУРА И СТЕК

### 2.1. Архитектура системы

Проект построен на микросервисной архитектуре с использованием Docker-контейнеризации:

```
┌─────────────┐
│   Nginx     │ ← Reverse Proxy
│  (Port 80)  │
└──────┬──────┘
       │
   ┌───┴───┬──────────────┬──────────────┐
   │       │              │              │
┌──▼──┐ ┌──▼──────┐  ┌───▼──────┐  ┌───▼──────────┐
│Front│ │ Backend │  │Database  │  │Background   │
│end  │ │ (API)   │  │(Postgres)│  │Service      │
│3000 │ │  3001   │  │  5432    │  │             │
└─────┘ └─────────┘  └──────────┘  └─────────────┘
```

### 2.2. Технологический стек

#### Frontend
- **React 18.2.0** - библиотека для построения пользовательского интерфейса
- **React Router 6.20.0** - маршрутизация в одностраничном приложении
- **Material-UI (MUI) 5.15.0** - библиотека компонентов для React
- **React Query 3.39.3** - управление состоянием сервера и кэширование
- **Axios 1.6.2** - HTTP-клиент для взаимодействия с API
- **date-fns 2.30.0** - работа с датами и временем
- **@emotion/react/styled** - стилизация компонентов

#### Backend
- **Node.js** - серверная платформа
- **Express 4.18.2** - веб-фреймворк для Node.js
- **PostgreSQL 15** - реляционная база данных
- **Sequelize 6.35.0** - ORM для работы с базой данных
- **JWT (jsonwebtoken 9.0.2)** - аутентификация и авторизация
- **bcryptjs 2.4.3** - хеширование паролей
- **Multer 2.0.2** - обработка загрузки файлов
- **Express Validator 7.0.1** - валидация входных данных
- **Helmet 7.1.0** - безопасность HTTP-заголовков
- **CORS 2.8.5** - настройка Cross-Origin Resource Sharing
- **Swagger (swagger-jsdoc, swagger-ui-express)** - документация API

#### DevOps и инфраструктура
- **Docker** - контейнеризация приложений
- **Docker Compose** - оркестрация контейнеров
- **Nginx** - reverse proxy и статический файловый сервер
- **Git** - система контроля версий

#### Дополнительные инструменты
- **Nodemon** - автоматическая перезагрузка сервера при разработке
- **Jest** - фреймворк для тестирования
- **Sequelize CLI** - миграции базы данных

### 2.3. Структура базы данных

Основные сущности:
- **Users** - пользователи системы (студенты, преподаватели, менторы, администраторы)
- **Projects** - учебные проекты
- **Teams** - команды для совместной работы
- **ProjectMembers** - участники проектов
- **TeamMembers** - участники команд
- **ProjectInvitations** - приглашения в проекты
- **TeamInvitations** - приглашения в команды
- **Comments** - комментарии к проектам
- **Ratings** - оценки проектов
- **Milestones** - этапы выполнения проектов
- **ProjectFiles** - файлы проектов
- **Activities** - история активности пользователей

## 3. ОПИСАНИЕ ФУНКЦИОНАЛА

### 3.1. Аутентификация и авторизация

**Реализованные функции:**
- Регистрация новых пользователей с выбором роли (студент, преподаватель, ментор)
- Вход в систему с использованием email и пароля
- JWT-токены для безопасной аутентификации
- Автоматическое обновление токенов
- Защищённые маршруты с проверкой прав доступа
- Система ролей с различными уровнями доступа

**Роли пользователей:**
- **Студент** - базовый доступ, создание проектов, участие в командах
- **Преподаватель** - расширенный доступ ко всем проектам и командам
- **Ментор** - доступ к публичным проектам и командам
- **Администратор** - полный доступ ко всем функциям системы, управление БД

### 3.2. Управление проектами

**Основной функционал:**
- Создание проектов с указанием названия, описания, статуса, видимости
- Редактирование проектов (только владелец, преподаватель или администратор)
- Удаление проектов с каскадным удалением связанных данных
- Управление видимостью: публичные и приватные проекты
- Отслеживание прогресса выполнения (0-100%)
- Архивирование и разархивирование проектов
- Добавление тегов к проектам
- Связывание проектов с репозиториями и демо-версиями

**Управление участниками:**
- Система приглашений в проекты
- Добавление участников через приглашения
- Удаление участников из проектов
- Отображение списка участников с аватарами

**Файлы проектов:**
- Загрузка файлов в проекты
- Просмотр списка загруженных файлов
- Скачивание файлов с авторизацией
- Удаление файлов

**Майлстоуны:**
- Создание этапов выполнения проекта
- Установка сроков выполнения
- Отметка выполнения этапов
- Редактирование и удаление майлстоунов

### 3.3. Управление командами

**Основной функционал:**
- Создание команд с указанием лидера, названия, описания
- Управление видимостью команд (публичные/приватные)
- Установка максимального количества участников
- Редактирование и удаление команд

**Система приглашений:**
- Отправка приглашений в команды
- Принятие и отклонение приглашений
- Отображение ожидающих приглашений
- История приглашений

**Управление участниками:**
- Добавление участников через приглашения
- Удаление участников из команд
- Отображение списка участников и лидера команды

**Связь с проектами:**
- Привязка проектов к командам
- Отображение проектов команды
- Создание проектов для команды

### 3.4. Социальные функции

**Комментирование:**
- Добавление комментариев к проектам
- Система ответов на комментарии (вложенные комментарии)
- Редактирование и удаление своих комментариев
- Отображение автора комментария с аватаром
- Переход на профиль автора комментария

**Рейтинги:**
- Оценка проектов по 5-балльной шкале
- Добавление текстовых комментариев к оценкам
- Отображение средней оценки проекта
- Удаление своих оценок

**Профили пользователей:**
- Просмотр профилей других пользователей
- Отображение информации о пользователе (имя, роль, биография)
- Просмотр проектов пользователя
- Просмотр команд пользователя
- Статистика пользователя
- Индикатор онлайн/оффлайн статуса
- Загрузка и отображение аватаров

### 3.5. Система уведомлений

**Функционал:**
- Уведомления о новых приглашениях в команды
- Уведомления о новых приглашениях в проекты
- Отображение количества непрочитанных приглашений

**Доступ:**
- Административная панель доступна только пользователям с ролью "admin"

**Swagger UI:**
- После запуска сервера документация доступна по адресу: `http://localhost:3001/api-docs`

**Основные эндпоинты:**

**Аутентификация:**

- `DELETE /api/projects/:id` - удаление проекта
- `POST /api/projects/:id/invite` - приглашение в проект
- `GET /api/projects/invitations` - приглашения в проекты
- `POST /api/projects/invitations/:id/accept` - принять приглашение
- `POST /api/projects/invitations/:id/reject` - отклонить приглашение

**Команды:**
- `GET /api/teams` - список команд
- `GET /api/teams/:id` - детальная информация о команде
- `POST /api/teams` - создание команды
- `PUT /api/teams/:id` - обновление команды
- `DELETE /api/teams/:id` - удаление команды
- `POST /api/teams/:id/invite` - приглашение в команду
- `GET /api/teams/invitations` - приглашения в команды
- `POST /api/teams/invitations/:id/accept` - принять приглашение
- `POST /api/teams/invitations/:id/reject` - отклонить приглашение

**Пользователи:**
- `GET /api/users` - список пользователей
- `GET /api/users/:id` - профиль пользователя
- `PUT /api/users/me` - обновление своего профиля
- `POST /api/users/me/avatar` - загрузка аватара
- `DELETE /api/users/me` - удаление аккаунта

**Файлы:**
- `POST /api/files/upload/:projectId` - загрузка файла
- `GET /api/files/:id` - скачивание файла
- `DELETE /api/files/:id` - удаление файла

**Статистика:**
- `GET /api/statistics` - общая статистика
- `GET /api/statistics/projects` - статистика по проектам
- `GET /api/statistics/user` - персональная статистика

**Администратор:**

- `GET /api/admin/users` - список всех пользователей

## 5. ИНСТРУКЦИИ ПО ЗАПУСКУ

### 5.1. Требования

**Системные требования:**
- Docker и Docker Compose (рекомендуется)
- Или Node.js 18+ и PostgreSQL 15+ (для запуска без Docker)

**Операционная система:**
- Windows 10/11
- Linux (Ubuntu 20.04+)
- macOS

### 5.2. Установка с использованием Docker (рекомендуется)

1. **Клонирование репозитория:**
   ```bash
   git clone <repository-url>
   cd educollab
   ```

2. **Запуск всех сервисов:**
   ```bash
   docker-compose up -d
   ```
   
   Эта команда запустит:
   - PostgreSQL базу данных
   - Backend API сервер
   - Frontend React приложение
   - Nginx reverse proxy
   - Background service

3. **Создание администратора:**
   ```bash
   docker-compose exec backend npm run create-admin
   ```
   
   Следуйте инструкциям для ввода email и пароля администратора.

4. **Проверка работы:**
   - Frontend: http://localhost:3000
   - Backend API: http://localhost:3001/api
   - Swagger документация: http://localhost:3001/api-docs
   - Nginx: http://localhost

### 5.3. Установка без Docker

#### Backend

1. **Установка зависимостей:**
   ```bash
   cd backend
   npm install
   ```

2. **Настройка переменных окружения:**
   Создайте файл `.env` в папке `backend/`:
   ```env
   NODE_ENV=development
   PORT=3001
   DB_HOST=localhost
   DB_PORT=5432
   DB_USER=educollab
   DB_PASSWORD=educollab_password
   DB_NAME=educollab
   JWT_SECRET=your-super-secret-jwt-key-change-in-production
   JWT_EXPIRES_IN=7d
   FRONTEND_URL=http://localhost:3000
   ```

3. **Настройка базы данных:**
   - Установите PostgreSQL
   - Создайте базу данных `educollab`
   - Создайте пользователя `educollab` с паролем `educollab_password`

4. **Применение миграций:**
   ```bash
   npm run migrate
   ```

5. **Создание администратора:**
   ```bash
   npm run create-admin
   ```

6. **Запуск сервера:**
   ```bash
   npm run dev
   ```

#### Frontend

1. **Установка зависимостей:**
   ```bash
   cd frontend
   npm install
   ```

2. **Настройка переменных окружения:**
   Создайте файл `.env` в папке `frontend/`:
   ```env
   REACT_APP_API_URL=http://localhost:3001/api
   ```

3. **Запуск приложения:**
   ```bash
   npm start
   ```

### 5.4. Первый вход в систему

1. Откройте браузер и перейдите на http://localhost:3000
2. Зарегистрируйте нового пользователя или войдите как администратор
3. Для входа как администратор используйте данные, созданные командой `create-admin`

### 5.6. Решение проблем

**Проблема: База данных не подключается**
- Проверьте, что PostgreSQL запущен
- Проверьте правильность данных в `.env` файле
- Убедитесь, что порт 5432 не занят

**Проблема: Frontend не может подключиться к Backend**
- Проверьте, что Backend запущен на порту 3001
- Проверьте настройки CORS в `backend/src/server.js`
- Проверьте переменную `REACT_APP_API_URL` во frontend

**Проблема: Файлы не загружаются**
- Проверьте, что папка `backend/uploads` существует и доступна для записи
- Проверьте настройки Nginx для статических файлов
